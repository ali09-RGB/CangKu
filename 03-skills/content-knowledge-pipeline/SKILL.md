# 内容 → 知识库流水线

把「某个领域的内容平台上讲得好的视频」变成「能检索、会过期、有判断的知识库」。

这个技能不是一套写死的脚本，而是**一条可换行业的流水线**：引擎（采集/转写/判定/归档）不动，行业知识全部外置在 `domain.json`，平台差异隔离在适配层。

## 三层结构：先分清哪层该改

| 层 | 包含什么 | 换它要动什么 |
|---|---|---|
| **引擎层** | 采集→判定→提取→转写→写报告→归档的流程与脚本 | **不动** |
| **平台适配层** | CDP 截流、接口端点、登录态、页面选择器 | 换平台（抖音→视频号）才动，属改代码 |
| **领域配置层** | 判定词表、主题分类、搜索关键词、术语校正、知识库目录 | **改 `domain.json` 即可** |

这三层混在一起，就会出现「想换个行业，结果要改判定代码」的困境。

## 四阶段总览

| 阶段 | 做什么 | 核心命令 | 详细步骤 |
|---|---|---|---|
| 一 · 环境 | 从裸机到能跑通一条链接 | 见参考文档 | `references/阶段一-环境搭建.md` |
| 二 · 采集 | 搜内容 → 判定 → 挑单 → 审批 | `browse.py` / `classify.py` / `rejudge.py` / `pick.py` | `references/阶段二-采集筛选.md` |
| 三 · 提取 | 下载媒体 → 转写 → 术语校正 → 写报告 | `batch.py` / `apply_terms.py` | `references/阶段三-提取与报告.md` |
| 四 · 归档 | 写库 → 同步 Obsidian → 索引 → 时效台账 | `sync.py` / `index.py` / `shelf.py` | `references/阶段四-归档.md` |

## 三条铁律（与行业无关，任何配置下都成立）

**一、改过判定配置，必须重判全库。**

```bash
python rejudge.py --dry                 # 先看影响
python rejudge.py --show-rejected 30    # 抽检被拒的，查误杀 ← 不能省
python rejudge.py                       # 确认后写库
```

只改配置不重判，库里的 `hit/topic/score` 还是旧规则算的，挑单照旧按旧分挑——等于白改。

**二、改配置，不要改代码。**

行业相关的东西一律放 `domain.json`。代码里的词表只是**兜底值**，配置存在时不起作用。改代码会让下一个行业继承你的临时决定。

**三、转写为空必须查清原因，不许凭标题写报告。**

转写为空有三种可能：提取失败（要重试）、真的没口播（如实记为无产出）、音频是音乐（同上）。**用标题推测内容凑一篇，是这条流水线里最严重的错误**，因为它会把编造的东西永久写进知识库。

## 换行业 / 换主题口径

改 `domain.json`，不要动脚本。字段含义、改动顺序、哪些情况必须改代码，见 `references/换行业指南.md`。

快速检查：

```bash
cd "$WS/工具"
python domain.py --check          # 看当前配置摘要
python classify.py --selftest     # 改完必须仍 100%
python rejudge.py --dry           # 再确认没误伤
```

## 常见意图对应动作

| 用户说 | 做什么 |
|---|---|
| 「继续跑一批采集」 | 读 `domain.json` 的主题分布 → 找最薄的 2~3 个主题 → 补关键词 → `browse.py --kwfile domain` |
| 「这几条要哪些」 | 读 `06-候选待审清单-N.md` → 给逐条判断与理由 → 等审批 |
| 「开始提取」 | 写 `links-batchN.txt` → `batch.py` → 逐条读转写 → 写报告 |
| 「入库」 | `sync.py` → `index.py` → `shelf.py` → 更新知识库首页 |
| 「这条为什么被拒」 | `classify.py "标题" --tags .. --author ..` 看 `reason` |
| 「换个行业」 | 见 `references/换行业指南.md` |

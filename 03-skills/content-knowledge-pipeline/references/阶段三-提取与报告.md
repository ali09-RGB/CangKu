# 阶段三 · 提取与报告

目标：把审批通过的链接，变成一份**能被人直接用的知识报告**。

## 1. 批量提取

```bash
python batch.py --links links-batch5.txt
```

约 40 秒/条（含下载 + 转写）。单条重试用：

```bash
python extract.py "https://www.douyin.com/video/<id>"
```

产出在 `素材包/<video_id>/`：

| 文件 | 内容 |
|---|---|
| `meta.json` | 标题、作者、发布日、时长、互动数据 |
| `audio.m4a` 或 `video.mp4` | 媒体本体 |
| `transcript.raw.txt` | 原始转写（校正前） |
| `transcript.txt` | 校正后转写 |

## 2. 三种媒体交付形态（都必须兼容）

这是整条链路最容易出血的地方，出过三次事故，每次形态都不同：

| 形态 | 特征 | 处理 |
|---|---|---|
| ① 音视频分两条流 | URL 带 `media-audio` / `media-video` | 按 CDN 路径 hash 配对，**必须**加时长校验（预加载会导致音轨属于下一条视频） |
| ② URL 无标识，只有 mime | 全是 `audio/mp4` 之类 | 按 mime 判类，排除 UI 资源；音频缺失要抛异常 |
| ③ 音轨合进视频容器 | 全是 `video/mp4`，但容器里有音频轨 | **不要把「没有独立音频流」当失败**，直接把 `video.mp4` 交给转写 |

形态 ③ 的判断方法：下载一段查容器 atom（`mp4a` / `soun` / `esds` 存在即有音轨）。

统一入口是 `extract.audio_source(outdir)`：有 `audio.m4a` 用它，否则用 `video.mp4`，都没有返回 None。
`transcribe()` 本来就是 PyAV 解码，解 mp4 里的 AAC 是原生能力，**不需要额外写「抽取音频」**。

> 改这类逻辑时注意：同一个判断条件往往出现在多处（内层下载、外层调用、批量脚本）。
> **只改一处会造成静默失败**——日志全正常，只是转写没跑、`meta.json` 里少一个字段。这比崩溃危险。

## 3. 术语校正（不能省）

```bash
python apply_terms.py --all
```

规则来自 `domain.json` 的 `terms`（旧版 `terms.json` 作为回退）。

ASR 错误密度约 **1.2 处/千字**，且高度集中在专业术语。危害不是错字难看，而是**会让人做错动作**：

| 错 | 对 | 危害 |
|---|---|---|
| 别单 | 憋单 | 术语本身错 |
| 低增 | 递增 | 意思相反 |
| 空成本 | 控成本 | 后台选项不同 |

处理原则：

- 高置信度同音错 → 进 `terms.replace`，直接替换
- 有歧义的 → 进 `terms.flag_only`，**只标注不改**（改错比不改更糟）
- 原始输出保留在 `transcript.raw.txt`，随时可回溯

繁简统一在同一个环节做（`opencc` 的 t2s）。

## 4. 写报告

**先读转写，再写报告。** 顺序不能反。

结构参考既有报告：

```markdown
---
sample_no: S0NN
video_id: '...'
author: ...
topic: <domain.json 里的主题名>
publish_date: 2026-08-03
duration_sec: 312
likes: 1104          # 视频本身的点赞，不是作者累计
collects: 856
source: https://...
archived_at: 2026-11-13
---

# 标题

> 一句话讲这条视频的核心贡献

## 一、它讲了什么（结构还原）
## 二、可执行的部分（步骤/公式/阈值）
## 三、边界与前提（什么情况下不适用）
## 四、与库里已有内容的关系（互补/重复/冲突）
```

三条写作要求：

1. **区分「能长期用的」和「必须先核实的」**。判断维度、决策顺序、因果机制放前者；具体数字、阈值、按钮位置放后者。
2. **不美化**。内容薄就如实写「本条信息量有限，主要贡献是一个判断维度」。凑字数会污染知识库的信噪比。
3. **标注与其他篇的关系**。「与 S014 的四步相比多了两步」这类信息比内容本身更有检索价值。

## 5. 什么时候判定「这条没有内容」

转写为空不要立刻重试，先分清：

| 情况 | 判断方法 | 处理 |
|---|---|---|
| 提取失败 | 媒体文件缺失或极短 | 重试 |
| 纯音乐 / 无口播 | 关掉 VAD 复跑，结果仍是歌词或空 | 如实记为无产出 |
| 干货在字幕里 | 音频有内容但无人声语义 | 如实记为无产出（需要 OCR 才能拿，属能力缺口） |

**不许用标题推测内容凑一篇报告。** 这是这条流水线里最严重的错误——它把编造的东西永久写进知识库，而且看起来和真报告一模一样。

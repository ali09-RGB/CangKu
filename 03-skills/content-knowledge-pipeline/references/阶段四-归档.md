# 阶段四 · 归档

目标：报告进库、能检索、知道什么时候会过期。

## 1. 写库并同步

```bash
python sync.py            # 素材包 + 报告 → SQLite + Obsidian
python sync.py --dry-run  # 先看会动哪些文件
```

`sync.py` 从 `domain.json` 读知识库路径与目录名（`vault.path` / `report_dir` / `index_dir`）。
`KNOWLEDGE_VAULT` 环境变量优先级更高，便于对比另一个库。

产出布局：

```
<vault>/<report_dir>/<主题>/S0NN-短名.md
```

## 2. 三个机械陷阱

**陷阱一：`sync.py` 只写入，不移动。**
改了 `topic` 后重跑 sync，新目录有了，**旧目录的文件还在**。结果知识库篇数比实际多。

> 改主题后的固定动作：`ls */<文件名>` 确认只有一个位置。

**陷阱二：库里的 `topic` 可能与内容不符。**
判定器按标题猜主题，长视频常猜错（讲投放的被判成数据复盘）。**以读完转写后的判断为准**，直接改库再 sync。

**陷阱三：首页是手工维护的。**
首页的统计数字（条数/字数/有效篇数）和篇目清单不会自动更新。新增报告后要手动改，否则首页会一直停在旧数字。

## 3. 索引

```bash
python index.py
```

重建样本索引表，写进 `01-投喂样本库.md` 的 `<!-- AUTO:INDEX:BEGIN/END -->` 标记区。

**这一段禁止手改**，下次运行会覆盖。手写索引出过错（把 2025 写成 2024，一年之差没人发现）。

## 4. 时效台账

```bash
python shelf.py           # 重算状态，写进 frontmatter
python shelf.py --check   # 巡检：哪些已超期、哪些快到
```

三级保质期：

| 级 | 类型 | 半衰期 | 判据 |
|---|---|---|---|
| A | 原理型 | 36 个月 | 依赖人的心理或决策顺序 |
| B | 方法论 | 12 个月 | 依赖平台机制 |
| C | 参数规则 | 3 个月 | 依赖后台按钮或具体数字 |

到期日 = 发布日 + 半衰期。

**混合型按最短的那段定级**，并在 note 里写清哪部分能信。例：「判断逻辑可长期用，但 20%/10% 两个阈值要按自己的数据校准」。

**一入库就已超期是正常的**，不是收录失误。品类红利按季度反转，后台参数按版本变。如实标注比假装它是新的更有价值。

状态三档：`现行有效` / `需复核`（到点了没人验证，**不代表错**）/ `已失效`（被新内容取代）。

状态**必须由日期算出来，不能手写**。手写的状态会和现实脱节，算出来的不会。

## 5. 首页

首页是知识库的入口，也是唯一需要人工维护的文件。新增报告后更新三处：

1. 顶部统计（条数 / 时长 / 字数 / 有效篇数）
2. 主题分组下的篇目清单（一行：篇名 + 核心句）
3. 如果有跨篇印证，补进「第一性原理」章节

**核心句写法**：一句话讲清这篇的独特判断，不要复述标题。例：
- 「追投不是加钱，是改速率——算出来比原来小，追了只会更慢」
- 「主播不行」不是原因，是放弃。能变成下一场动作的，才叫原因

## 6. 收尾核对

```bash
ls <vault>/*/S0NN*.md | wc -l     # 确认篇数
python shelf.py --check           # 确认没有意外的「已失效」
```

篇数对不上，先查重复文件（陷阱一），再查库里 `topic` 是否为空（会落到「未分类」）。

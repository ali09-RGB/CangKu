## 一、为什么要做这件事

知识库最容易骗人的地方，**不是「讲错了」，而是「当时讲对了，现在失效了」**。
前者一眼能看出来，后者在库里和有效内容长得一模一样。

这事已经在库里真实发生过：

```
S001（2025-11）教 5+2+1 憋单
   ↓
S004（2025-12）说不会憋单也能做平播
   ↓
S020（2026-03）明确说「新规之后不能再用这个憋单了」
```

现在库里 S001 还叫「5+2+1 憋单法」，标题看着和别的报告一样权威。
**如果不管，它就是一颗定时炸弹——哪天您照着做，踩的是两年前的规则。**

## 二、分级标准

分级依据只有一个问题：**这个东西失效的驱动因素是什么？**

| 级别 | 名称 | 半衰期 | 失效驱动 | 典型内容 |
|---|---|---|---|---|
| **A** | 原理型 | 36 个月 | 底层机制 / 人性心理，平台换代仍成立 | 人性七宗罪、拉停留的认知缺口、要不要投流的决策框架 |
| **B** | 方法论 | 12 个月 | 打法结构，平台大改会部分失效 | 平播七步、软逼单结构、话术四步进阶 |
| **C** | 参数规则 | 3 个月 | 后台按钮 / 出价数字 / 平台新规，改版即废 | 五维四率指标名、千川按钮操作、随心推参数 |

**到期日 = 发布日 ＋ 半衰期。** 不是入库日 —— 一条 2025-09 讲随心推参数的视频，
失效的起点是它描述的那个平台状态，不是我们发现它的那天。
按入库日算会系统性高估新鲜度，这是最容易犯的错。

## 六、复核怎么做

```bash
python 工具/shelf.py --check      # 日常巡检：只看过期和临期
python 工具/shelf.py              # 重新生成本台账
```

复核一篇 C 类内容，实际动作是：**把报告里的数字和后台对照一遍**。
对得上 → 改 `verified` 日期，续期；对不上 → 状态改 `expired`，写明被什么取代。

**注意区分 `review` 和 `expired`**：

- `review` = 到点了没人验证过，**不代表错**，可能完全有效
- `expired` = 有明确证据失效（被新规推翻 / 被后续样本纠正）

把这两个混为一谈，就会误删还有用的内容。

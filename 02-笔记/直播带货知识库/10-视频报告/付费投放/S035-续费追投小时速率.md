# S035 · 续费追投：先算小时速率，再决定追多少

> [!caution] ⚠️ 参数已过保质期，但公式还在（2026-11-12 标注）
> **等级 C（参数规则）｜ 发布 2026-03-21 ｜ 状态：需复核**
>
> 按 C 级 3 个月算，已超期约 **145 天**。
>
> **可以信的**：`小时速率 = 预算 ÷ 投放时长` 这个换算逻辑，以及「追投预算要揉进整场摊平」这个认知。
> 这两条是原理，不随后台改版。
> **要先核实的**：随心推后台的追投入口、时长选项、日预算下限——这些八个月里大概率改过。
>
> 参照物：`08-时效性台账.md`｜时效分级依据：D-26

> **一句话价值**：追投不是「再加一笔钱」，是**改变整场的消耗速率**。
> 追之前先算一件事：追完之后每小时的预算，比原来高还是低？
> 高了流速涨，低了流速降——**很多人追完单量反而掉了，就是没算这个。**

## 为什么追投会「越追越慢」

作者开场点出了目的：

> 「如果说你想要破层级、想要出业绩，就一定要学会做**场中追投**。」

但追投有个反直觉的陷阱：**加钱不一定加速**。

举一个具体的数字（作者自己的例子）：
- 原订单：3000 元 / 3 天 / 每天投 2 小时
- 第一天投了 1 小时，消耗 200 元
- 此时决定追投 600 元 / 3 小时

直觉上「我加了 600 块，肯定跑得更快」。但算一下就变了：

```
原订单小时预算 = 3000 ÷ 3 天 ÷ 2 小时 = 500 元/小时

续费后小时预算 = (500-200 + 600) ÷ (2-1 + 3)
              = 900 ÷ 4
              = 225 元/小时
```

**225 < 500**，所以续费后的跑量预期是**下降**的。

为什么？因为你加了钱，也加了时长——而且加的时长（3 小时）比原来剩下的时长（1 小时）长得多，
把预算摊薄了。

## 两个公式

### 公式一：原订单的小时速率

```
原订单小时速率 = 原订单预算 ÷ 原订单总投放时长
```

作者的口语版本：

> 「比如说你 200 块投 4 小时，就用 200 除 4，那每小时的消耗速率就是 50 块，对不对。」

### 公式二：续费后的小时速率

```
续费后小时速率 = (原订单剩余预算 + 续费预算) ÷ (原订单剩余投放时长 + 续费时长)
```

**注意分子是「剩余预算」不是「原预算」**——已经花掉的不算。
作者例子里分子是 `500 - 200 + 600`，那个 `500-200` 就是「3 天内还剩的预算」（简化算法）。

## 三条判断规则

算完两个数，直接对比：

| 对比结果 | 预期效果 |
|---|---|
| 续费后 = 原订单 | 保持流速不变 |
| 续费后 **>** 原订单 | 流速**上升**（拉高跑量） |
| 续费后 **<** 原订单 | 流速**下降**（这就是上面那个例子） |

作者的原话：

> 「如果我们想要保持续费之后跑量速度不变、流速不变，那我们就得保证：续费后的小时预算 **等于** 原订单的小时预算。
> 比如说我们想提升跑量速度、拉高流速，那我们就得保证：续费后的小时预算 **要大于** 原订单的一个小时预算。」

**这就把「追投」从直觉变成了算术。** 想加速，不是「加钱」，是「让每小时的预算变大」。

## 核心技巧：高预算、短时长，一小时一小时追

这是全篇最实用的一条，也是作者反复强调的重点：

> 「教大家一个追投的核心技巧：**不要那个 3 个小时、5 个小时这样子去做追投**。
> 一定是**高预算、短时长**去做追投——1 个小时、1 个小时去做一个追投。
> 因为你 3 个小时、5 个小时做追投的话，它的**起量速度是会比较慢**的。」

为什么短时长起量快？回到公式就明白了：

同样的钱，摊在 1 小时上是高小时速率（跑得猛），摊在 5 小时上是低小时速率（跑得温）。
**时长是分母，拉长分母就是稀释。**

而且这解释了前面的例子为什么流速会降——他追投了 3 小时，把预算摊薄到了 225/小时。

## 一个认知上的转变

作者最后点了一句，比技巧更重要：

> 「总之，追投的逻辑应该是**把你续费后的预算，揉进整场直播当中去做消耗**，
> 而不是像之前标准投放一样，必须把追投的预算在几个小时之内就消耗完。」

这句话改变了追投的目的：
- **旧理解**：追投 = 花掉一笔钱（所以恨不得几小时烧完）
- **新理解**：追投 = 调整这一场的**消耗节奏**（所以要看小时速率，而不是看总预算）

按新理解，「这笔钱多久花完」不重要，「每小时花多少」才重要。

## 一个必须要提醒的地方

这条的所有数字（3000 元、3 天、2 小时、600 元）都是**举例**，不是推荐参数。
它真正给的是**一个算法**：拿你自己的数字代进去算。

而且计算里有一个简化：分子用 `500-200`（即「3 天总预算 3000 中剩下的」简化为「小时预算减已消耗」），
严格算应该是「剩余总预算 ÷ 剩余总时长」。**作者的算法是个速算近似**，
代入你自己的数据时，建议用严格版本复核一次。
